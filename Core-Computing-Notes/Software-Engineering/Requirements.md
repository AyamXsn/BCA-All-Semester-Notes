# Requirements and Use Cases

## 1. Requirement
A requirement states a capability, constraint, or quality the system must satisfy.

## 2. Functional requirements
Describe system behaviour, such as registering a user, calculating a total, or generating a report.

## 3. Non-functional requirements
Describe quality attributes or constraints, such as response time, accessibility, security, availability, and supported platforms. Make them measurable where possible.

## 4. Elicitation
Requirements can be gathered through interviews, observation, questionnaires, workshops, document analysis, and prototypes.

## 5. Use case
A use case describes how an actor interacts with a system to achieve a goal. It can include preconditions, main flow, alternative flows, and postconditions.

## 6. Validation
Check requirements for correctness, completeness, consistency, feasibility, and testability. Ambiguous statements should be clarified.

## 7. Exercise
Write functional and measurable non-functional requirements for a library lending system.
