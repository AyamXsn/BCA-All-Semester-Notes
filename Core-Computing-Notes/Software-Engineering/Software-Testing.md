# Software Testing

## 1. Purpose
Testing evaluates software and reveals defects. Testing can increase confidence but cannot prove the absence of all defects.

## 2. Black-box and white-box
Black-box testing derives tests from expected behaviour without relying on internal code structure. White-box testing uses internal structure, branches, paths, or data flow to guide tests.

## 3. Test design techniques
Equivalence partitioning divides input into groups expected to behave similarly. Boundary-value analysis tests values at and near limits. Decision tables cover combinations of conditions. State-transition testing checks state changes.

## 4. Regression testing
Regression tests check that changes have not broken existing behaviour.

## 5. Automation
Automated tests are repeatable and useful in continuous integration, but test maintenance and quality still require care.

## 6. Exercise
Design test cases for a marks-to-grade function, including boundary and invalid values.
